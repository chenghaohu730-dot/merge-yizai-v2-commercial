## 1. 已锁定的 V2.0 决策

以下内容不再作为讨论项，直接按此实施。

### 1.1 技术路线

- V2.0 正式运行版统一迁移到 Cocos Creator 3.8 LTS + TypeScript。
- game/web-prototype 和 game/wechat-minigame 冻结为 V1 行为、数值、平台适配、测试方法和代码实现参考；V1 视觉、美术资产和既有美术风格不得作为 V2 生产输入。V1 双端只允许修复线上紧急缺陷，不再同时扩展三套功能。
- game/cocos-creator-v2 是 V2.0 正式工程根，但当前只是骨架；必须补齐真实场景、Prefab、编辑器挂载、微信构建和真机测试。
- 物理规则先做行为对齐和自动化基准，再根据真实局长数据调优。不能在迁移过程中顺手改手感。
- 微信、Web 预览、云服务差异全部放入平台适配层，核心玩法、配置、存档、任务、皮肤和榜单数据结构只保留一份。

### 1.2 分包和画质

- 必须做分包加载。
- 不允许为了主包或分包限制，把角色、UI、特效压糊、缩小到失真，或继续保留廉价代码绘制资源。
- 包体超预算时，优先拆分主包、本地功能分包和逐皮肤本地 Asset Bundle，再做无损去重、图集与真机通过的纹理优化；不得把角色、UI 或特效压糊。
- 默认头像链、首页、核心玩法、结算和基础音频必须以商业质量进入本地核心玩法包。
- 所有可解锁皮肤随审核包内置，每套皮肤独立进入微信普通分包；玩家完成解锁后直接加载并使用，不做 CDN、远程下载或下载缓存。
- 每个本地 Bundle 必须记录版本、SHA256 和准确字节数；资源回滚随完整客户端审核版本进行，不做运行时远程资源热更。

### 1.3 联网排行榜

- V2.0 必做全服联网排行榜。
- 每个完成首局有效对局的玩家自动入榜，不要求先授权微信头像昵称，不设置“只有前 100 名才算上榜”的资格线。
- 页面可以按 Top100、我的名次、附近名次和游标分页分批加载，但数据库中必须保存全部有效上榜玩家。
- 只接受云函数提交，客户端不能直接写排行榜集合。
- 客户端显示的分数不是可信数据；服务端必须重新计算分数并做对局合法性校验。
- V2.0 首发榜单包含全服周榜、赛季榜和历史最高榜。好友榜不是满足本需求的替代品，可作为后续增强。

### 1.4 美术生产

- V2 美术执行“全量重制”：旧背景、UI、按钮、面板、头像、皮肤、图标、粒子、宣传图、音频和旧风格均不得继承、改色、缩放、裁切、拼接、图生图或重新导入。
- V2 美术风格不受 V1 糖果合成机方案约束；先用 4–6 个方向重新探索，再由用户选择正式风格。
- 可以对标《开心消消乐》等头部休闲游戏的商业完成度、层级、色彩、触感与反馈节奏，但不得复制其角色、Logo、图标、布局、按钮轮廓、文案或可识别商业外观。
- 所有当前由 Canvas、CSS 或代码形状承担的可见装饰美术必须替换为正式美术资源。
- 所有正式可见像素必须来自本轮 Grok 新生产母版及其可追溯的确定性派生，不允许从旧图“复审后继续使用”。
- 动态分数、最高分、倒计时、玩家名、名次、任务进度、货币数量和错误文案继续由程序实时绘制，不能烘焙进图片。
- 除品牌 Logo 外，按钮文字原则上也由程序叠加，避免生成模型写错中文并为后续改文案留余地。
- 程序可以负责布局、九宫格、裁切、透明度、点击区域、动态文字、粒子发射逻辑和物理运动；程序不能再用圆形、渐变、胶囊和色块冒充正式角色、按钮、面板、背景或特效素材。
- Grok 用于生成和编辑图片、视频；正式接入前先检测真实命令行接口，不得凭空编造 Grok CLI 参数。

### 1.5 亿仔和版权

所有涉及亿仔的生成和编辑任务，必须把本机 `art/source/yizai_highest_source.png` 作为唯一正式身份参考，并在任务清单中记录其 SHA256 `6B6C74F39FB8A92E8CD7B23BDD729D2E14BD76E38DE4C0CB0AD528638A7BCD12`。如果当前 Grok 能力不能真实读取参考图，则停止亿仔任务，不能仅凭文字生成。

所有正式亿仔必须同时满足：

- 白熊主体。
- 橙黄色口鼻区。
- 黑色大鼻子。
- 粗眉毛。
- 头部有装饰物。
- 头饰正面清晰、正确、未遮挡地显示 MAEE。
- MAEE 不得省略、替换、拼错、镜像、倒置或被遮挡。

前 10 级头像和所有皮肤必须原创。可以借鉴网络梗图的情绪和荒诞气质，但不得复制真人脸、现成角色、原表情包图、平台水印或受版权保护的独特造型。

当前事实：

| 项目 | 当前状态 | V2.0 处理 |
| --- | --- | --- |

## 3. V2.0 最终成品定义

V2.0 不是“V1 加几个按钮”，而是达到以下闭环：

1. 核心局内闭环：手感稳定、失败节奏合理、反馈有层级、长局不卡顿。
2. 资源交付闭环：主包轻、核心包完整、皮肤全部内置、逐包 hash 可追溯、画质不降级。
3. 局外留存闭环：任务和成就产出亿仔币，亿仔币解锁皮肤，皮肤在局内、榜单和分享卡中展示。
4. 全服竞争闭环：有效对局自动入榜，玩家能看到准确的自己名次、附近名次和完整分页榜。
5. 微信传播闭环：结算展示名次变化，动态分享卡展示分数、皮肤和合规亿仔。
6. 商业运营闭环：埋点、受控配置、错误监控、构建版本、灰度、整包回滚和可选激励广告。

V2.0 暂不做复杂剧情、抽卡、重商城、多地图、强制账号注册和改变物理公平性的付费属性。

## 4. 目标工程架构

推荐数据流：

    微信主包 Boot
      ├─ 读取本地版本与随包资源清单
      ├─ 初始化微信云开发身份
      ├─ 校验本地 bundle manifest 与构建 hash
      └─ 加载 core_game 本地分包
            ├─ Home
            ├─ Game
            └─ Result
                 ├─ 空闲预取 meta_ui
                 ├─ 解锁后加载 skin_* 本地普通分包
                 ├─ 云函数提交有效对局
                 └─ 全服榜 Top / Around Me / Page

代码层：

| 层 | 责任 |
| --- | --- |
| domain | 物理规则、得分规则、任务规则、皮肤规则、排行榜排序规则 |
| application | 开局、结算、存档、资源加载、对局提交、领取和装备流程 |
| presentation | Cocos 场景、Prefab、动画、UI 状态 |
| platform | WeChat、Web 预览、音频生命周期、震动、分享、网络 |
| backend | CloudBase 云函数、数据库、定时任务、风控和排行快照 |
| content | 美术、音频、视频、Asset Bundle、manifest |

核心规则不得直接依赖 wx 全局对象。所有微信调用从 WechatAdapter 或后续平台适配接口进入。

## 5. 本地分包与资源执行方案

### 5.1 平台硬限制与内部预算

| 项目 | 平台口径 | 项目内部门禁 |
| --- | --- | --- |
| 主包 | 不超过 4M | 不超过 3.3 MiB |
| 主包 + 本地分包 | 不超过 20M | 目标不超过 16 MiB，保留热修和平台差异空间 |
| 普通分包 | 平台当前文档不限制单个普通分包 | 仍按功能拆分，避免首次下载过大 |
| 独立分包 | 不超过 4M | V2.0 首发不依赖独立分包 |
| 逐皮肤本地 Bundle | 计入主包与分包总量 | 每套独立普通分包，纳入逐包和总包字节门禁 |

包体脚本必须同时输出字节数和 MiB，不能只看文件夹体积。发布前以微信开发者工具实际构建结果为最终判定。

### 5.2 包划分

| 包名 | 类型 | 内容 | 加载时机 |
| --- | --- | --- | --- |
| main | 微信主包 | 引擎启动最小集、Boot、Loading、错误兜底、平台适配、版本与资源清单读取 | 冷启动 |
| core_game | 本地普通分包 | 默认 11 级头像、首页、核心玩法、结算、核心字体、基础 BGM/SFX、必要 VFX | 进入首页前 |
| meta_ui | 本地普通分包 | 设置、任务、成就、商店、全服榜 UI、通用弹窗和状态页 | 首页空闲时预取，点击功能时兜底加载 |
| skin_classic_v2 | core_game 内默认资源 | 商业质量经典头像链 | 核心包加载时 |
| skin_jelly_v2 | 本地普通分包 Asset Bundle | 首发皮肤 1、预览、局内贴图、榜单徽章 | 解锁后或装备时 |
| skin_star_v2 | 本地普通分包 Asset Bundle | 首发皮肤 2、预览、局内贴图、榜单徽章 | 解锁后或装备时 |
| skin_cream_v2 / skin_coin_v2 / skin_festival_v2 | 各自独立的本地普通分包 Asset Bundle | 其余随包内置皮肤 | 解锁后或装备时 |
| audio_extra | 本地普通分包 Asset Bundle | 扩展 BGM、皮肤主题音和活动音频 | 设置或皮肤启用时 |
| media_showcase | 不进入游戏运行包 | 宣传与商店展示视频另作发布物 | 不在小游戏运行时下载 |

首发建议是全新默认套 + 两套完整长期皮肤。现有 `jelly`、`star`、`cream`、`coin`、`festival` 只允许保留为主题 ID、数据结构和分包命名参考；旧图片、角色造型和视觉风格一律不得复用。

### 5.3 Cocos Asset Bundle 配置

- core_game 和 meta_ui 配置为 Asset Bundle。
- 微信平台下使用“小游戏分包”压缩类型。
- 每个 skin_* 配置为本地 Asset Bundle，并在微信平台构建为普通分包；不得勾选远程包。
- Bundle 入口目录只放场景、Prefab、清单或需要动态加载的入口资源，避免把无引用原图全部打进包。
- 皮肤 Bundle 不放业务脚本；脚本随审核过的本地包发布。
- 打开构建文件名 hash，并在随包 manifest 中保存 bundleVersion、sha256、bytes 和 minClientVersion；此处是构建完整性记录，不是远程下载缓存。
- 退出商店或卸下皮肤后按引用计数释放非当前皮肤资源，不能一进入商店就把所有皮肤常驻内存。

### 5.4 启动与加载流程

1. Boot 读取随当前审核包发布的本地 manifest。
2. 初始化 wx.cloud；网络状态只影响联网榜等在线功能，不影响皮肤可用性。
3. 校验客户端版本、本地资源清单和核心包状态。
4. 调用 assetManager.loadBundle 加载 core_game，显示真实进度，不允许假进度条。
5. core_game 成功后进入 Home；失败时展示正式错误页，提供重试和网络说明。
6. Home 首帧稳定后预取 meta_ui。
7. 玩家解锁或装备某个皮肤时，加载随包内置的对应 skin_* 普通分包。
8. 清单或资源缺失时保持当前皮肤并回退正式 classic_v2，记录可定位错误；不出现半套资源。
9. 资源版本回滚通过微信审核版本和 Git 构建锚点完成，不在运行时切换远程 manifest。
10. 宣传视频不进入小游戏关键路径；游戏内只使用随包静态海报或本地轻量动画。

### 5.5 画质不让位于包体的执行规则

- 原始母版永久保留，不允许优化工具覆盖母版。
- 全屏背景母版建议至少 1500×2668；运行导出不得低于 750×1334，最终尺寸由真机锐度和内存 A/B 决定。
- 头像母版建议 1024×1024，运行版本为 512×512；透明安全区和圆形碰撞轮廓保持一致。
- 非透明大背景优先高质量 JPG；带透明边缘的头像、按钮、面板和特效使用 PNG。
- 九宫格只用于可拉伸的中部材质，边框、角色和高光不可被整张强拉伸。
- 图集用于减少 DrawCall，不得因自动裁切破坏透明边缘或碰撞中心。
- 硬件纹理压缩只能在低端 Android、主流 Android 和 iPhone 真机均通过后开启，并保留兼容回退。
- 若资源超预算，先做本地逐皮肤拆包、重复资源消除、图集和经真机 A/B 通过的格式优化；不得直接把清晰角色压成模糊贴图。

### 5.6 资源清单最小字段

每个可发布资源至少记录：

| 字段 | 含义 |
| --- | --- |
| assetId | 稳定资源 ID |
| logicalPath | 逻辑路径 |
| bundle | 所属主包或本地普通分包 Bundle |
| version | 资源版本 |
| sha256 | 完整性校验 |
| bytes | 文件大小 |
| width / height | 像素尺寸 |
| alpha | 是否透明 |
| nineSlice | 九宫格参数 |
| preload | 是否预加载 |
| fallbackAssetId | 失败回退资源 |
| sourcePrompt | Grok 任务或人工来源记录 |
| license | 授权与版权记录 |
| minClientVersion | 最低兼容客户端 |

## 6. 全服联网排行榜执行方案

### 6.1 首发后端选择

V2.0 首发采用微信云开发 CloudBase：

- 小游戏端用 wx.cloud.init 和 wx.cloud.callFunction。
- 云函数端用 cloud.getWXContext 取得可信 OPENID。
- 不把 AppSecret、OPENID 或数据库写权限暴露给客户端。
- 排行榜、对局记录和风控集合设置为仅管理端可写。
- 所有读写通过云函数收口，后续如果数据量增长，可以在保持接口不变的前提下迁移到云托管 + Redis 排名服务。

若正式 AppID 尚未关联 CloudBase，可先完成本地 mock 和 dev 环境代码；真实榜验收必须使用正式 AppID、真实云环境和至少两个微信账号。

### 6.2 “所有玩家均可上榜”的产品定义

- 玩家无需注册独立账号。
- 云函数第一次识别新 OPENID 时生成内部 playerId。
- 未授权微信资料时，自动显示“亿仔玩家 + 四位公开编号”和游戏内默认头像。
- 玩家完成第一局通过服务端校验的对局后，自动创建周榜、赛季榜和历史榜记录。
- 不要求达到最低分，不要求进入 Top100，不要求分享。
- Top100 只是首屏展示方式；玩家总能看到自己的真实名次，并能通过游标继续浏览全量榜。
- 纯离线启动且未取得服务端 runId 的对局只保存本地，不承诺上榜；已有有效 runId 的对局可在规定时间内断网重试提交。

### 6.3 榜单口径

| 榜单 | 周期 | 排序 | 重置 |
| --- | --- | --- | --- |
| 周榜 | 周一 00:00 至下周一 00:00，中国标准时间 | 最佳成绩 | 自动新建 periodId |
| 赛季榜 | 远程配置定义 | 最佳成绩 | 赛季关闭后冻结快照 |
| 历史榜 | 永久 | 历史最佳成绩 | 不重置 |

固定同分排序：

1. score 降序。
2. maxLevel 降序。
3. durationMs 升序。
4. achievedAt 升序。
5. playerId 升序，保证结果稳定。

### 6.4 数据集合

#### players

私有玩家身份，不直接返回 OPENID。

| 字段 | 说明 |
| --- | --- |
| _id | 服务端 playerId |
| openid | 仅服务端可见 |
| publicCode | 可展示编号 |
| displayName | 默认系统名或审核后的用户昵称 |
| avatarId | 游戏内头像 ID |
| equippedSkinId | 已装备皮肤 |
| createdAt / lastSeenAt | 服务端时间 |
| status | active / restricted / banned |

#### run_sessions

| 字段 | 说明 |
| --- | --- |
| _id | runId |
| playerId | 所属玩家 |
| nonce | 一次性随机值 |
| seed | 本局掉落序列种子 |
| configVersion | 数值配置版本 |
| clientVersion | 客户端版本 |
| startedAt / expiresAt | 服务端时间 |
| status | started / finished / expired / rejected |

#### run_results

保存全部已提交对局和审核结果。

| 字段 | 说明 |
| --- | --- |
| runId / playerId | 对局和玩家 |
| clientScore | 客户端上报分数，仅供对比 |
| serverScore | 服务端按合成事件重算分数 |
| maxLevel | 最高等级 |
| durationMs | 局长 |
| dropCount | 掉落次数 |
| mergeCounts | 各等级合成次数 |
| yizaiCount | 亿仔次数 |
| eventDigest | 压缩事件日志摘要 |
| riskFlags | 异常规则命中 |
| verdict | valid / review / rejected |
| completedAt | 服务端完成时间 |

#### leaderboard_entries

每个玩家、每个周期只保留一条最佳成绩。

| 字段 | 说明 |
| --- | --- |
| _id | periodId + playerId，天然保证唯一 |
| periodType / periodId | week / season / all |
| playerId | 玩家 |
| score / maxLevel / durationMs | 排序字段 |
| achievedAt | 首次达到该最佳成绩的服务端时间 |
| bestRunId | 对应有效对局 |
| displayName / avatarId / equippedSkinId | 公开展示快照 |
| status | visible / review / hidden |

#### rank_snapshots

- 保存 Top100 和赛季结算快照。
- 降低首页排行反复聚合压力。
- 快照不是全量榜的唯一数据源，不能把第 101 名以后丢掉。

#### remote_config 与 asset_manifests

- 保存赛季时间、数值版本、最低客户端、资源版本、功能开关和回滚版本。
- 客户端只读经过签名或云函数返回的白名单字段。

### 6.5 必要索引

至少建立：

- players.openid 唯一索引。
- run_sessions 的 playerId + startedAt 降序索引。
- run_results 的 playerId + completedAt 降序索引。
- run_results.runId 唯一索引。
- leaderboard_entries 的 periodId + status + score 降序 + maxLevel 降序 + durationMs 升序 + achievedAt 升序组合索引。
- leaderboard_entries 的 periodId + playerId 唯一性由 _id 保证。
- riskFlags、verdict 和 completedAt 的运营复核索引。

全量翻页使用游标，不使用页码越大越慢的深度 skip。

### 6.6 云函数接口

| 云函数 | 输入 | 输出 | 要点 |
| --- | --- | --- | --- |
| profileGet | 无或客户端版本 | 公开玩家资料、装备皮肤、服务端时间 | 自动创建玩家 |
| runStart | clientVersion、configVersion | runId、nonce、seed、expiresAt、服务端配置 | 一次性对局凭证 |
| runFinish | runId、事件摘要、局长、统计 | verdict、serverScore、各榜名次变化 | 幂等，只能完成一次 |
| rankTop | periodId、limit | Top 列表、我的名次 | 默认 100，上限受控 |
| rankAroundMe | periodId、radius | 我的前后若干名 | 无论排名多低都可查询 |
| rankPage | periodId、cursor、limit | 全量榜下一段和 nextCursor | 游标分页 |
| rankHistory | seasonId | 冻结赛季结果 | 只读 |
| profileUpdate | avatarId、可选昵称 | 清洗后的公开资料 | 昵称必须审核 |
| configGet | clientVersion | 远程配置和资源清单版本 | 白名单返回 |

runFinish 必须放在服务端事务中完成：

1. 验证 runId 所属 OPENID。
2. 验证状态和过期时间。
3. 重算分数和风险规则。
4. 写 run_results。
5. 若本局更好，更新三个 leaderboard_entries。
6. 把 run_session 标记为 finished。
7. 返回名次和名次变化。

重复提交同一 runId 必须返回第一次结果，不得重复写奖励或覆盖更好的榜单记录。

### 6.7 最低反作弊标准

- 分数只能由 mergeCounts 和服务器版本的得分表重算。
- runStart 的 seed 决定掉落等级序列，客户端不能自行声明稀有掉落。
- 检查掉落次数、合成守恒、最高等级、局长、最短掉落间隔、警戒结束条件和版本号。
- 检查一个 runId 只完成一次、nonce 不复用、提交未过期。
- 按 playerId、设备摘要和 IP 风险维度限流，但不公开保存不必要的原始隐私数据。
- 极端高分、异常短局、版本不一致和统计不守恒进入 review，不立即出现在公开榜。
- 服务端和客户端都记录 configVersion，旧版本异常分数不能混入新赛季。
- 承认客户端游戏无法做到绝对防作弊；目标是阻止简单改分、重放、批量刷分，并让高分可审计。

### 6.8 排行榜 UI

排行榜必须包含：

- 周榜、赛季榜、历史榜标签页。
- Top3 视觉区。
- Top100 列表。
- 固定“我的名次”行。
- “我附近”入口，展示前后各 5 至 10 名。
- 继续加载全量榜的游标列表和虚拟滚动。
- loading、empty、offline、timeout、server error、under review 和 retry 状态。
- 未授权资料玩家的系统昵称和默认头像。
- 已装备皮肤徽章，不能显示未下载的大图作为首屏阻塞项。

首屏接口目标：

- rankTop 和 rankAroundMe 在正常网络下 P95 小于 800 ms。
- runFinish 在正常网络下 P95 小于 1500 ms。
- 超时先保留本地结算并进入重试队列，不能卡死结算页。

### 7.3 商业美术风格基线

V1 的糖果合成机只属于历史方案，不是 V2 已锁定方向。V2 先制作 4–6 个明显不同、可实际落地的商业风格方向，由用户看 Golden Slice 后选择。方向探索至少覆盖：高完成度明亮休闲消除感、精致 3D 玩具感、现代 2.5D 插画感等，但不得在确认前把任一方向写成正式基线。

共同质量底线：

- 可以对标《开心消消乐》等头部休闲游戏的信息层级、色彩节奏、触感、反馈丰富度和全页面一致性，不得复制其可识别美术表达。
- 玩法区保持低干扰，头像和合成反馈始终比背景更醒目。
- 光源方向、边缘高光、投影软硬、描边粗细、圆角和图标透视在选定方向内统一。
- 首页、局内、结算、商店和排行榜必须属于同一原创产品视觉系统，不能拼接模板。
- 前 10 级头像由本轮从零设计角色身份；皮肤只能基于这套新角色参考表变化材质、配色、边框和局部装饰。
- 第 11 级亿仔是最高价值视觉锚点，必须使用本机正式参考图生成，不能被特效遮住 `MAEE`。
- 任何旧 V1/V2 图片都不能作为新方向的组件母版或生成参考。

### 7.5 MAEE 专项流程

生成模型对字母准确性不可靠，正式流程必须是：

1. 只以 `art/source/yizai_highest_source.png` 作为身份基准，并校验 SHA256 为 `6B6C74F39FB8A92E8CD7B23BDD729D2E14BD76E38DE4C0CB0AD528638A7BCD12`。
2. 每个涉及亿仔的 Grok 任务必须显式携带或读取该参考图；工具不支持参考图时停止该任务，不允许降级成纯文字生成。
3. Grok 生成时要求头饰正面留出清晰、完整、无遮挡的字标区域。
4. 生成后用受控图片编辑把从正式参考源提取并批准的标准 `MAEE` 字标贴合到头饰透视，而不是让运行时代码画字。
5. 检查字母顺序、大小写、镜像、倒置、遮挡和缩略图清晰度。
6. 对所有出现亿仔的头像、结算、图标、分享图、皮肤、视频逐帧抽查。
7. OCR 只能辅助，最终必须人工放大 200% 复核。

任何一个字母错误，该资源整批不得进入 art/final。

### 8.4 生成顺序与闸门

#### A. 美术圣经

先废止把 V1 糖果机当成唯一方向的旧口径，再生成 4–6 套风格方向板。每套都要能解释首页、局内、按钮、弹窗、原创头像和合成反馈。用户选定后才锁定：

- 色板。
- 材质板。
- 光照和阴影规则。
- UI 圆角、边框、高光和描边规则。
- 图标透视与线条规则。
- 头像链身份卡。
- 亿仔标准参考页。

退出条件：能用同一规则解释首页、游戏页、按钮、弹窗和头像，不再出现多个互相冲突的视觉体系。

#### B. Golden Slice

每个风格方向只做以下代表资源，不使用任何旧图像素或旧图参考：

- 首页完整概念图。
- 局内完整概念图。
- 主按钮三态。
- 通用弹窗和一条排行行。
- face_01、face_05、face_10。
- face_11_yizai。
- 一次普通合成特效。

先提交 4–6 个风格方向供用户初选；进入候选短名单后，每项再生成 2 至 3 个候选，自动筛掉文字错误、版权风险、结构错误、旧图复用和风格漂移，只把 1 至 2 个合格版本交给用户确认。

退出条件：两张整屏和代表组件在同一屏拼装时一致，亿仔规范 100% 通过。

#### C. UI Kit

按已锁定方向批量生成：

- 首页。
- 局内 HUD、机器框、玻璃和控制台。
- 通用按钮 normal / pressed / disabled / selected / loading。
- 暂停、确认、设置。
- 任务、成就、商店、排行榜。
- 结算、分享、加载、空态、离线和错误状态。

先生成无文字底板，再由 Cocos 叠加文字。品牌 Logo 可以单独作为正式美术。

#### D. 默认头像链和皮肤

- 前 10 级从零建立一套原创角色身份，不继承旧头像轮廓、五官、配色或贴图。
- 第 11 级只使用本机正式亿仔参考图生成。
- 先完成全新的 11 级默认链。
- 再以这套全新角色参考表制作 jelly_v2；旧 jelly 图片不得复用。
- jelly_v2 全部通过后再做 star_v2。
- 其他皮肤不在首发关键路径批量生成。
- 每个皮肤都要与本轮新批准的默认角色表比较，确认轮廓、五官和情绪仍可识别。

#### E. 特效与视频

- 普通合成、高级合成、亿仔成功、金币飞行、按钮点击使用透明序列帧或粒子贴图。
- 视频只用于非交互关键路径：2 至 3 秒启动氛围、3 至 5 秒皮肤展示、6 至 15 秒营销素材。
- 游戏内若使用短动画，必须随包本地交付并有同构图静态海报；营销视频作为包外发布物，不由小游戏运行时下载。
- 局内核心玩法不使用持续播放视频背景，避免干扰、发热和内存压力。

### 8.5 每张图的验收

- 尺寸、格式、透明通道和命名正确。
- 透明边缘无白边、黑边和脏像素。
- 视觉中心和锚点正确。
- 同类资源的相机角度、光照、材质和阴影一致。
- 没有模型水印、平台水印、乱码、错误中文和无关文字。
- 没有现成 IP、真人脸或原表情包复制。
- 头像轮廓不超出物理安全区。
- 亿仔的 MAEE 正确且缩小后仍可辨识。
- 皮肤只改视觉，不改物理参数。
- 记录生成模型、提示词、参考图、种子、人工修改和 SHA256。

### 8.6 禁止一次性盲生成

以下行为禁止：

## 19. 当前官方技术依据

- 腾讯小游戏分包加载：主包不超过 4M，主包与分包总计不超过 20M，并提供 wx.loadSubpackage 与进度回调。  
  https://intl.cloud.tencent.com/zh/document/product/1219/68072

- Cocos Creator 3.8 Asset Bundle：本项目只采用本地 Bundle 和微信小游戏普通分包，通过 assetManager.loadBundle 加载，并记录构建版本 hash。  
  https://docs.cocos.com/creator/3.8/manual/en/asset/bundle.html

- Cocos Creator 3.8 小游戏分包配置：Asset Bundle 可构建到微信小游戏 subpackages。页面中的包体总量数字若与腾讯平台当前文档冲突，以腾讯平台实测为准。  
  https://docs.cocos.com/creator/3.8/manual/zh/editor/publish/subpackage.html

- CloudBase 微信端云函数：wx.cloud.callFunction 可自动携带用户身份，云函数使用 getWXContext 取得 OPENID。  
  https://docs.cloudbase.net/recipes/add-cloud-function-wechat-miniprogram

- CloudBase 索引：排行榜的多字段筛选与排序必须建立对应组合索引。  
  https://docs.cloudbase.net/database/data-index

- CloudBase 安全规则：敏感集合应通过安全规则和服务端写入收口。  
  https://docs.cloudbase.net/database/security-rules

- CloudBase 事务：多集合一致性事务只在服务端 Node SDK 执行。  
  https://docs.cloudbase.net/database/transaction

- 微信小游戏 API TypeScript 类型定义：用于平台接口的类型基线。  
  https://github.com/wechat-miniprogram/minigame-api-typings
